# Ingest toolkit (P1b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `prismql ingest` turns any table or a harness log folder into a Parquet stream the engine loads without config, optionally with an embedding column the server reads instead of recomputing.

**Architecture:** `src/prismql/ingest/` — a core (`normalize`, `embed`, `write`) over Polars, source adapters under `sources/` (each: path → DataFrame in canonical columns), a CLI dispatched from the `prismql` script. Dataset-specific joins stay outside the package (workspace Makefile) and hand one table to `table`. The server reads `emb` from Parquet into `SemanticIndex`.

**Tech Stack:** Polars, pyarrow, sentence-transformers (extra `[ingest]` = `[semantic]`).

**Spec:** graph `@aleph/prismql` #54 (kriya), #56/#57 (log formats), `docs/superpowers/specs/2026-09-18-ordinal-axis-design.md` layer 1.

## Global Constraints
- Canonical columns: `position` int64 = row index after sort; `id` (unique); `time` = Arrow `timestamp[us, UTC]` (null when unparseable); `emb` = `FixedSizeList<float32, d>` when requested.
- The engine never joins; adapters never guess: an unknown record shape in a harness log raises, it is not skipped silently.
- Both dialect references untouched (no surface change). `STATE.md` in the same commit as each stage.
- Stage commits with explicit paths; owner pushes.
